# ตั้งค่า Login และบัญชีผู้ใช้

ระบบเข้าสู่ระบบด้วยชื่อผู้ใช้หรืออีเมลและรหัสผ่าน กำหนดสิทธิ์จากบัญชีที่ admin สร้างไว้ ตรวจสิทธิ์บน Apps Script ทุกครั้งที่เรียก API อ่าน/เขียนข้อมูล

## สร้าง admin บัญชีแรก

1. คัดลอก `Index.html` และ `รหัส.gs` เวอร์ชันล่าสุดเข้าโปรเจกต์ Apps Script เดิม
2. เปิด **Project Settings → Script properties** แล้วเพิ่ม:

   | Property | ค่า |
   |---|---|
   | `AUTH_MAINTENANCE_EMAIL` | อีเมล Google ที่ใช้เปิด Apps Script Editor แบบเต็ม เช่น `your.name@example.com` ไม่ใช่ Username ของเว็บ |
   | `AUTH_BOOTSTRAP_USERNAME` | ชื่อผู้ดูแลที่ต้องการ เช่น `admin` |
   | `AUTH_BOOTSTRAP_PASSWORD` | รหัสผ่านที่กำหนดเอง ยาว 12–128 ตัวอักษร |
   | `AUTH_BOOTSTRAP_NAME` | ชื่อที่แสดง (ไม่บังคับ) |

3. กดบันทึกค่าคุณสมบัติ กลับไป Editor บันทึกโค้ด แล้วเลือกฟังก์ชัน **`setupInitialAdmin` (ไม่มี `_` ต่อท้าย)** กด **Run** ด้วยบัญชี Google ที่ระบุใน `AUTH_MAINTENANCE_EMAIL` และอนุญาตการทำงานเมื่อ Google ขอ เมื่อสำเร็จ Execution log จะแสดงชื่อบัญชี admin ที่สร้าง
4. เมื่อสำเร็จ ระบบสร้างบัญชี admin และลบ property `AUTH_BOOTSTRAP_PASSWORD` อัตโนมัติ ไม่ต้องใส่รหัสผ่านลงในซอร์สโค้ด
5. เปิด **Deploy → Manage deployments → Edit → New version → Deploy** ใช้ **Execute as: Me** เพื่อให้ผู้ใช้เว็บเข้าถึงข้อมูลผ่านสิทธิ์ของเจ้าของสคริปต์ แล้วกำหนดผู้ที่เข้าเว็บได้ให้ตรงกับกลุ่มใช้งาน
6. เปิด URL เว็บแอปและเข้าสู่ระบบด้วยบัญชีที่สร้าง จากเมนู **จัดการผู้ใช้** เพิ่มบัญชี `employee`, `user` หรือ admin เพิ่มเติมได้

`setupInitialAdmin`, `unlockLogin`, `resetAdminPassword` แสดงในรายการ Run และตรวจอีเมล Google ของผู้เรียกให้ตรงกับ `AUTH_MAINTENANCE_EMAIL` ทุกครั้ง หากอีเมลว่างหรือไม่ตรงจะปฏิเสธ ฟังก์ชันภายในที่ลงท้าย `_` ไม่แสดงในเมนู Run และเรียกผ่าน `google.script.run` ไม่ได้ การสร้างบัญชีเริ่มต้นซ้ำจะถูกปฏิเสธเมื่อมีบัญชีอยู่แล้ว ห้ามเผยแพร่รหัสผ่าน bootstrap หรือให้ผู้ใช้ทั่วไปมีสิทธิ์แก้ไขโปรเจกต์ Apps Script

## หากเข้าสู่ระบบไม่ได้หรือถูกล็อก 15 นาที

การล็อกเก็บใน Script Properties ของเซิร์ฟเวอร์ การรีเฟรชเว็บไม่ล้างตัวนับ การลองซ้ำขณะล็อกไม่เลื่อนเวลาปลดล็อก

1. นำ `รหัส.gs` เวอร์ชันล่าสุดไปบันทึกใน Apps Script
   ตั้ง `AUTH_MAINTENANCE_EMAIL` เป็นอีเมล Google แบบเต็มที่ใช้รันฟังก์ชันใน Editor
2. เปิด **Project Settings → Script properties** เพิ่ม `AUTH_RECOVERY_USERNAME` เป็นชื่อบัญชีที่ต้องการปลดล็อก เช่น `admin` หากไม่ใส่ ระบบจะใช้ `AUTH_BOOTSTRAP_USERNAME` เดิม
3. กลับ Editor เลือก **`unlockLogin` → Run** เพื่อล้างตัวนับของบัญชี แล้วลอง Login อีกครั้งด้วยรหัสผ่านเดิม ไม่ต้อง Deploy ใหม่หากต้องการเพียงล้างตัวนับ
4. หากขึ้นว่าชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง ให้ตรวจชื่อบัญชีที่ใช้สร้างจริง การปลดล็อกไม่ได้เปลี่ยนรหัสผ่านหรือเปิดบัญชีที่ถูกระงับ

หากลืมรหัสผ่าน **admin**:

1. กำหนด `AUTH_RECOVERY_USERNAME` ให้ตรงกับชื่อ admin ที่มีอยู่
2. เพิ่ม `AUTH_RECOVERY_PASSWORD` เป็นรหัสผ่านใหม่ ยาว 12–128 ตัว
3. รัน **`resetAdminPassword`** ใน Editor ระบบจะตั้งรหัสผ่านใหม่ เปิดบัญชี ล้างการล็อก และยกเลิก session เดิม พร้อมลบ `AUTH_RECOVERY_PASSWORD` อัตโนมัติ
4. ลอง Login ด้วยรหัสผ่านใหม่ ส่วนข้อความแสดงเวลารอที่ปรับปรุงแล้วต้อง **Deploy เวอร์ชันใหม่** จึงจะปรากฏในเว็บ

ถ้าฟังก์ชันแจ้งว่าไม่พบบัญชี ให้ตรวจชื่อก่อน หากยังไม่เคยสร้างบัญชี ให้ทำขั้นตอน **สร้าง admin บัญชีแรก** ด้านบน ห้ามลบ Script Properties ทั้งหมด เพราะจะทำให้ข้อมูลบัญชีหาย

ใช้ฟังก์ชันกู้คืนที่ไม่มี `_` จากรายการ Run ของ Editor โดยเข้าสู่ Google ด้วยอีเมลผู้ดูแลที่ตั้งไว้ การตั้งค่าอีเมลนี้ให้สิทธิ์สร้าง admin และกู้คืนบัญชี จึงต้องระบุเฉพาะบัญชีที่เชื่อถือได้ ระบบจะไม่ใช้อีเมลเจ้าของ deployment แทนอีเมลผู้เรียก

## การใช้งาน

- **admin:** ดูรายงาน เพิ่ม/แก้ไข/ลบข้อมูล นำเข้าทั้งแบบต่อท้ายและแทนที่ ตั้งค่าเมนู/คอลัมน์ และจัดการบัญชี
- **employee:** ดูรายงาน เพิ่ม/แก้ไขข้อมูล และนำเข้าแบบต่อท้ายที่ใช้คอลัมน์เดิม
- **user:** ดูรายงาน dashboard พิมพ์/PDF และดาวน์โหลด Excel

หน้า Login ไม่มีตัวเลือก role สิทธิ์มาจากข้อมูลบัญชีบนเซิร์ฟเวอร์ ผู้ใช้ที่ลืมรหัสผ่านติดต่อ admin ให้ตั้งรหัสผ่านใหม่ในหน้าจัดการผู้ใช้

admin เพิ่มอีเมลได้ในหน้า **จัดการผู้ใช้ → แก้ไข → อีเมล → บันทึกการแก้ไข** จากนั้น Login โดยกรอกชื่อผู้ใช้หรืออีเมลพร้อมรหัสผ่านเดิมได้ อีเมลเป็นข้อมูลเสริม ไม่บังคับสำหรับบัญชีเดิม และต้องไม่ซ้ำกับชื่อผู้ใช้หรืออีเมลของบัญชีอื่น หากล้างช่องอีเมลแล้วบันทึก บัญชีนั้นจะกลับมาใช้ชื่อผู้ใช้เข้าสู่ระบบอย่างเดียว

การแก้ไขบัญชีจะให้บัญชีนั้น Login ใหม่ รวมถึง admin ที่แก้ไขบัญชีของตนเอง ระบบป้องกันการระงับหรือลดสิทธิ์ admin คนสุดท้าย

ในหน้าจัดการผู้ใช้ กด **แก้ไข** เพื่อเปลี่ยนชื่อผู้ใช้ ชื่อที่แสดง สิทธิ์ และสถานะได้ ชื่อผู้ใช้ใหม่ต้องไม่ซ้ำกับบัญชีอื่น หากไม่เปลี่ยนรหัสผ่านให้เว้นช่องรหัสผ่านว่าง เมื่อเปลี่ยนชื่อแล้วต้อง Login ด้วยชื่อใหม่ หากต้องกู้คืนภายหลังให้ใช้ชื่อใหม่นี้ใน `AUTH_RECOVERY_USERNAME`

กด **เพิ่มบัญชีใหม่** เพื่อล้างข้อมูลในฟอร์ม กลับสู่โหมดสร้างบัญชี โดยค่าเริ่มต้นเป็น role `user` และเปิดใช้งานบัญชี ไม่ต้องลบข้อมูลแต่ละช่องเอง

session หมดอายุภายใน 6 ชั่วโมงหรือเร็วกว่านั้นหาก Script Cache ถูกล้าง ปุ่มออกจากระบบจะยกเลิก session ของแท็บนั้น หากเปิดหลายแท็บ แต่ละ session แยกกัน

ใช้สิทธิ์แชร์ Google Sheets และ Apps Script แยกจาก role ภายในเว็บ ผู้ที่มีสิทธิ์แก้ไขไฟล์ต้นทางยังแก้ไขข้อมูลโดยตรงได้ ควรให้สิทธิ์ไฟล์ต้นทางเฉพาะผู้ดูแลที่จำเป็น และอัปเดตหรือปิด deployment เก่าที่ยังไม่มีระบบ Login ด้วย

## ทดสอบใน workspace

```sh
node tests/auth.test.cjs
node tests/auth-ui.test.cjs
```

ทดสอบการแฮชเทียบกับ Node crypto, การปฏิเสธ API ตาม role, การป้องกันชีตระบบ, การจัดการ session, การจำกัดการลอง Login, การป้องกัน admin คนสุดท้าย และการทิ้งผลลัพธ์จากบัญชีก่อนหน้า

ก่อนใช้งานจริงให้ทดสอบทั้ง 3 role บน URL deployment: Login, ดูรายงาน, เพิ่ม/แก้ไขข้อมูลตามสิทธิ์, ออกจากระบบ และ Login กลับอีกครั้ง การทดสอบใน workspace จำลองบริการ Google และ DOM ไม่ได้เรียก Apps Script จริง
